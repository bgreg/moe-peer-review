01

The idea

A single reviewer has one blind-spot map. Eight reviewers with deliberately incompatible priorities have almost none, provided something forces them to argue.

Ordinary AI review collapses to one voice with one set of instincts. This plugin breaks that voice into eight agents who cannot agree by construction: a security engineer who reads everything as an attack surface, a compliance officer who reads it as an audit exhibit, and a furious non-technical end user who cannot read it at all.

Findings are squeezed along two independent axes before reaching you. Phase 3 tests claims against evidence, with the moderator trying to falsify each one against the actual code. Phase 4 tests claims against other experts, with the moderator stepping out entirely. The bet is that these two filters fail differently, so what survives both is unusually likely to be real.

Review-only, and it is enforced

The guarantee is not a promise in a prompt. The eight persona agents are declared with tools: [Read, Grep, Glob], so they do not possess a tool capable of writing a file. Every run ends with a literal STOP before anything is acted on.

02

The panel

Each persona file is a full character: education, career history, emotional affect, pet peeves, and an explicit list of who they clash with in debate. That last section is a wiring diagram of which arguments will happen, and it is what manufactures the disagreement the process depends on.

Two constraints keep the characters from becoming noise. Stay in your lane forbids reviewing outside your domain, capped at one sentence for cross-lane concerns. Graduated severity forces every finding into one of three buckets.

Blocker

Production failure, data loss, security breach, or audit failure.

Warning

Fix before launch; not immediately dangerous.

Suggestion

Raises quality. Not required.

03

How it executes

The most important structural decision: the moderator is not a subagent. Her file says so explicitly. The main conversation reads it and becomes her.

The reason is visibility. A subagent's work is compressed into a final report, and only its return value reaches you. Because the moderator runs in the main context, every exchange prints live and you watch the review happen.

The eight personas are spawned once, in parallel, then resumed, never respawned. Their agent IDs live in moe-state.json, which is what lets a persona carry its Phase 1 memory into Phase 4, and what makes recovery after context compaction possible.

04

The five phases

  1. Kick-Off
    kick-off · 8 agents spawned in parallel

    Material presented cold, with conversation context deliberately withheld so reactions aren't anchored to prior conclusions. Each persona first verifies three claims against the real repository, then returns 5–7 observations. The moderator only confirms receipt.

  2. Clarifying Questions
    clarifying-questions · 8 agents resumed

    Each persona asks 5–7 precise questions. The moderator answers from source material and by reading actual code, and must admit "not documented" where the gap is real rather than inventing coverage.

  3. Interactive Session
    interactive-session · moderator vs. agent · cap 100/agent

    The adversarial fact-check. Default posture is disbelief; the burden of proof sits with the agent. The phase must produce exactly 2N blocks for N personas, and closes with a Blocker Re-Test Ledger, a Consensus Ledger, and the moderator's public self-check.

  4. The Huddle
    the-huddle · agent vs. agent · cap 100 + 100/agent

    The moderator steps back and relays messages between experts. Anyone leaving Phase 3 with open items must participate. Closes with a participation checklist marking gaps.

  5. Synthesis
    synthesis · moderator alone

    Ten required sections, deduplicated, ordered by severity. An empty section still prints its header with "None identified". Then a literal STOP.

05

What it sounds like

Every phase prints as a first-person, blockquoted chat thread. Third-person narration is banned, because summarizing a persona is exactly how a model quietly drops the specifics. The exchanges below are adapted from a recorded 728-line review, condensed for length.

ChaoticCarl (End User, compliance-analyst backstory)
Category A is still coming back "Unknown" and I can't tell if it's actually fixed. How would I even tell the difference between "actually fixed" and "broken again" from the report alone? And why do I have to deal with AI behavior at all? If I run the same vendor twice and get different scores, how do I explain that to Legal?
Dr. Nina Simone-Bennett -> ChaoticCarl
Noted. Your first and last points aren't separate complaints, they're the same worry three technical reviewers found independently from three different angles. Beyonce found the model call that decides your score has no temperature set. Janelle found the test meant to catch that regression is off by default in CI. Whitney found a malformed response renders as a clean "Unknown" with no error. You're not wrong to not trust it yet.
Phase 3 · verify, refuse, or refute — there is no fourth option
SZA -> Dr. Nina Simone-Bennett
An attacker with read access to the job queue could replay a completed payload and overwrite the verdict field. There is no nonce and no idempotency key on that path.
Dr. Nina Simone-Bennett -> SZA
I cannot verify this: I read the queue consumer and found no nonce, which matches your structural claim. But I could not establish that the verdict field is writable post-completion, since the status guard may block it. Carrying as a Warning, not a Blocker, until the call path is confirmed.
The exchange that justifies the design

Two specialists propose fixes that look complementary. The collision reveals that one would break the other, and produces a third design neither had proposed.

Phase 4 · the moderator is silent; experts collide
Doechii -> Whitney Houston-Davis
Your fabrication finding is sharper than mine and I'm not contesting it. But they're not the same root cause. Yours is fabrication under absence: no data, so the model invents one. Mine is trust-calibration on data that is present, where a cited legal document and an uncited guess get the identical "exact and authoritative" stamp.
Whitney Houston-Davis -> Doechii
Orthogonal, both must ship. Critical warning: if your gate is built as a filter that drops sub-threshold facts, it converts populated-but-uncertain cells into empty ones, which is indistinguishable from never-measured. That makes my fabrication bug worse, not better. Recommend: label, don't filter. A three-state provenance model as two fields on one type, not two separate patches.
ChaoticCarl -> Beyonce Carter
Explain it like I'm five. What does "temperature zero" actually look like for me? What's the override command? And would Monday's score and Wednesday's score match?
Beyonce Carter -> ChaoticCarl
Temperature zero is one line in a config file, invisible to you, and worth doing. But it does not guarantee reproducibility, because the deciding step runs a fresh live web search every time regardless of the randomness dial. There is no override flag anywhere in the CLI. Same vendor Monday and Wednesday: no guarantee of an identical number. Nobody has measured how much it moves, which is exactly the missing data point.

A non-technical demand for plain language forced a senior engineer to trace a claim to its end, and the trace ended at an unmeasured variable nobody had noticed. ChaoticCarl did not find that. He caused it to be found.

06

What stops the rubber stamp

The obvious failure mode for a panel of agreeable AI reviewers is unanimous, evidence-free approval. Six mechanisms exist to prevent it, and most of them were added because a real run drifted past a softer version of the same rule.

MechanismRule
Three-response ruleEvery factual claim gets "I verified this" with file:line, "I cannot verify this", or "This is incorrect". Bulk acceptance is forbidden.
2N block countPhase 3 produces one persona block and one moderator block per persona. The moderator counts her own blocks before printing.
Blocker Re-Test LedgerTry to disprove that a confirmed fact causes the claimed harm. Every Blocker reaching Synthesis needs a row, or it is not eligible.
30% self-auditIf more than 30% of responses lack one of the three templates, pause and re-verify.
Self-incrimination checkBefore the Huddle, answer publicly: "Did I reject any claim? If not, why not?"
Consensus LedgerPrinted every round even when there is nothing to report, so "no disagreements" is a stated finding rather than an absence.
07

Guardrails and self-validation

Read-only enforcement is layered five deep, and the layer doing the real work is the least conspicuous: the persona agents literally do not possess a tool that writes. The skill preamble, the per-persona "No file modifications" line, and the closing STOP are reinforcement.

After writing the transcript, the moderator runs the transcript validator and prints its output verbatim. The validator diagnoses; it does not clean up. The transcript is never edited to make a failing check pass, because it is a faithful record and editing it would hide the very problem the check reported.

The improvement loop

A background agent receives the transcript and the validator output, scores the run on six dimensions, and classifies every failure as MODEL EXECUTION (the guidance was adequate and was not followed) or PLUGIN GUIDANCE (the plugin never asked, or asked ambiguously). Suggestions land in plugin-improvements.md with the exact file, current text, and proposed replacement. Nothing is applied automatically, and the next run reads that file first.
